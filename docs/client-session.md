# 客户端与会话协议

本文只描述当前 Frame 版本 3 及方向校正必须保留的执行边界，不混用早期版本行为。原始定义见 [client.proto](../crates/tok-proto/proto/tok/client/v1/client.proto)，代码用法见 [Rust 用户指南](../crates/tok/docs/guide.md)，旧版本记录见[协议演进历史](client-session-history.md)。

gateway 是通用服务设施的扩展，连接与会话状态机仍承担本协议。目标执行上下文和消息/事件 Layer 见[服务运行模型](service-runtime.md)，实现顺序见[实施计划](implementation-plan.md)。本轮未授权改变现行客户端协议；新增接口不得绕过认证、所有权或 session FIFO。

## TCP 分帧与消息

开发适配使用明文 TCP，每帧是 4 字节大端长度和 protobuf Frame，长度只计正文，必须大于零且不超过 max_frame_size；分配缓冲前检查长度。完整帧读/写都有期限，包含等待首字节的时间。半帧 EOF、非法长度、解码和版本错误会结束该连接，是否保留 session 按宽限期处理；当前没有独立心跳。

Frame.version 必须为 3，只接受该版本。控制、业务和内部来源的分发表独立；客户端不能发送 Notify、Response 或服务器事件/timer。字段详情以 proto 为准。

| 消息对或消息 | 作用 | 下行序列/缓存 |
| --- | --- | --- |
| LoginRequest / LoginResponse | credential 普通登录，或有效 token 快速重登；两者二选一 | 不进入 |
| BusinessRequest / BusinessResponse | request_id 关联，message_id 选择业务类型 | 已绑定 session 的 Response 进入，含业务/框架失败 |
| Notify | 服务器主动下行，不与请求配对 | 进入，与 Response 共用序列 |
| ControlError | 未认证或非法控制流程的错误 | 不进入 |
| Ack | 客户端确认已连续应用的最大下行序号 | 不进入 |
| ResumeRequest / ResumeResponse | token + ack_seq 恢复原逻辑 session；返回身份及已见最大业务请求 ID | 不进入 |
| RecoveryComplete | 说明 through_seq 之前的补发已完成，可以恢复业务交互 | 不进入 |
| RefreshResumeTokenRequest / Response | 已认证在线连接刷新 token 与 TTL | 不进入 |

控制请求与业务请求的 request_id 在当前连接非零、严格递增；内部 timer/事件的执行序号独立，不占客户端请求计数。跨重连客户端保留已发送最大 ID，并结合 ResumeResponse.last_request_id 选择更大的新 ID，不重发未知结果请求。

## 会话、认证与所有权

连接绑定一次传输接入；session 保存逻辑玩家身份、FIFO、timer、主题和下行缓存，跨连接可以继续存在。认证得到可信 player_id 后才取得所有权并建立会话；客户端业务正文不能选择另一个玩家身份。

普通登录创建新的 session_id。顶号先使旧入口失效、收束本地在途调用，按所有权条件操作更新 epoch 与最新会话标记；旧 token 不能恢复新会话，也不能在新会话释放后再建立旧身份。普通登录不能直接抢占其他网关的活动租约。

SessionHandle 不是可任意修改的状态引用，提交操作仍检查当前身份与阶段。MemoryOwnership 只协调单进程，多个网关选择共享 Redis；发现配置与所有权后端独立。

## FIFO、事件与 timer

客户端请求、服务器转发事件、timer 经同一 session FIFO。在线准入、容量、所有权和剩余预算检查必须保留；RPC 或注入 Executor 都受执行期限约束，不自动重试。超时后远端仍可能运行，沿[系统异常边界](design.md#系统异常边界)处理。

Notify 不执行 player；服务器事件可以转换为 Notify，也可以转发进 FIFO。当前即时事件仅向在线、已登录、非补发、非冻结的会话准入，不拉起未知/离线玩家。topic 成员由可信服务器管理，当前只影响本地索引；动态传输兴趣是后续 P5/P6 的能力。

TimerSpec 由服务器业务通过结果返回，客户端不能指定框架 timer ID、内部消息、周期或产出。ReplaceAll 全量替换，空集合清空；Patch upsert/cancel 按 ID 更新，None 保持现状。版本校验淘汰旧票据，更新先完整校验后应用；非法或超容量更新关闭 session，不能继续沿用不一致配置。

单个 timer 至多有一个待执行/执行中触发。一次性过期尽快执行一次并移除；周期错过多次时合并为一次，沿原基准计算下一未来时刻，不逐次追赶。scheduled_at_ms 是预定时刻，fired_at_ms 是实际触发时刻。UTC 与单调时钟在 session 创建时对齐，后续不因墙钟跳变重放。

断线宽限期内 timer 继续运行；同网关恢复沿用当前调度，快速重登由业务全量初始化。没有固定的 player 登录 RPC，游戏显式恢复状态与 ReplaceAll。

## 下行序列、确认与缓存

Response 与 Notify 在同一 session 内从 server_seq=1 连续编号，0 表示无已发布消息，溢出停止会话。request_id 只关联请求，不决定下行次序；后续请求的即时拒绝可以先于前一个在途业务回应发布。

发布先完成帧大小及回应转换校验，再分配序号、保存最终编码字节和提交连接发送队列。超大通知不消耗序号，控制消息不进入业务缓存。发布成功表示缓存接受，不等于 socket 写完或客户端收到。

Ack 只能由当前绑定提交。零、重复和倒退确认忽略；超过缓存已提交上界的确认返回错误并按协议收束。客户端只能确认已连续应用的位置，有缺口时不能跳过确认；重复下行不重复应用业务。ACK 不证明客户端确实执行业务，也不提供请求幂等。

缓存以单调时间、条数及编码字节限制，允许淘汰未确认记录。ACK 释放已确认记录，原始保留时间不会因读取或交接延长。replay_after 查询当前位置后的连续范围，缺口/越界返回不可恢复；不发送、不确认、不重新执行 RPC。

新下行的用户 Layer 必须在编号、编码和缓存之前执行，补发只发送原始字节，不再经过同一业务中间件。读取快照可延长字节的引用生命期，调用方及时释放。

## 同网关恢复与快速重登

断线仅解除绑定，默认保留 session、所有权、timer 和缓存 30 秒。旧连接的迟到关闭、提交和 ACK 按绑定代次拒绝，不能影响已恢复的新连接。宽限期到期停止新工作，收束在途调用、条件释放所有权，清理会话资源。

ResumeRequest 使用有效 token 和 ack_seq：恢复原 session_id 与序列，失效旧绑定，先发送 ResumeResponse，再补发原序号消息，最后发送 RecoveryComplete。补发过程中新的下行只入缓存并继续追平；客户端等待完成标记再发业务。补发缺口、缓存/身份不匹配或状态不可用返回 ResumeUnavailable，不静默跳过。

恢复成功不重新执行已请求业务，不自动签发新 token。旧 session 不可恢复但凭证仍有效时，使用 LoginRequest.resume_token 快速重登，创建新 session 和序列，由游戏获取全量业务状态；它不是恢复原 session。过期、顶号失效或不可接受的历史标记改走普通 credential 登录。

## 恢复凭证与刷新

ResumeTokenCodec 是本地签发与验证契约，SignedResumeTokens 使用 HMAC-SHA256 固定共享密钥，不读 Redis 或数据库。签名提供完整性，凭证内容可解码，不提供保密。

默认临时密钥重启后变化；参与跨网关的进程在 `[resume_token]` 配置相同的 32 字节十六进制 secret_key。clock_skew_ms 默认 5000，仅容忍签发时刻领先，不延长过期。默认 token 身份有效期 1 小时，与 30 秒会话宽限期独立。恢复/交接不续期，维护换密钥并重启会使旧 token 失效，不提供热轮换或密钥环。

在线已认证且恢复完成的连接可用新 request_id 刷新，不提交旧 token；旧 token 到期不取消在线刷新资格。操作与顶号/交接串行协调，先条件续租再校验当前绑定、非补发/冻结状态，签发并返回同一 session_id 的新 token 和 TTL。刷新不重置 epoch、序列、timer 或宽限期；旧 token 仍按原到期时间有效，不维护逐 token 撤销表。

客户端在新 TTL 到期前主动刷新，预留网络与调度余量；回应丢失时在线可用新的 request_id 再次请求，离线且凭证过期则普通登录。顶号标记及 acquire_for_relogin 比较属于所有权协调，不是凭证验签时查询 Redis；旧会话的整组 token 因身份标记被拒绝。

## 跨网关交接

默认关闭。开启要求共享所有权、共用签名密钥、可发现且可访问的 GatewayRpc 内部端点，容量与期限配置有效。新网关 B 本地验签并从所有权定位源网关 A，不经客户端指定任意源节点。

| 阶段 | 源网关 A | 目标网关 B |
| --- | --- | --- |
| 准备 | 停止准入与 timer 产生，排空已接收任务，封存快照并继续有效续租 | 验签、预留容量、校验快照，尚不驱动 player |
| 提交 | 串行协调提交与取消，按完整旧身份执行条件所有权转移；提交开始不再自行解冻 | 等待条件接管结果，保留 session_id，使用增加后的 epoch |
| 接续 | 旧入口永久失效并条件清理 | 安装快照、受监督执行、恢复绑定并补发 |
| 取消或过期 | 仅在确认未转移且身份有效时恢复原入口；否则停止旧驱动 | 释放本次准备资源，不释放其他所有者租约 |

快照保留完整源身份、业务请求进度、timer/事件内部序号、topic、连续缓存原字节及剩余保留时间。Job::Snapshot 在 FIFO 中等待前序任务完成再取执行快照；冻结与暂停动作由交接流程提前执行。不能迁移 future、Sender、连接绑定或 Instant，也不搬迁半执行 Job。

目标扣除准备往返耗时，重验缓存连续性和剩余期限，不重置旧宽限期或缓存 TTL。正常交接保留 session_id、下行序号与 timer 基准，增加 epoch。冻结窗口的新通知/转发事件拒绝或跳过，不额外积压；源挂掉、快照缺失或缓存有缺口时降级快速重登。

提交结果不确定时先按 handoff_id 查询，不盲目重新提交、回滚或同时恢复两端。准备期限监督不依赖请求 future 存活；客户端断开也要清理/恢复准备状态。完成通知丢失不阻止新所有者运行，旧端通过所有权变化或期限收束，不能释放新端租约。

未来动态主题兴趣在目标准备阶段建立并就绪，取得所有权前不向目标会话投递；源端取消/提交按 P6 规则恢复或清理。迁移业务主题及显式扩展快照，不迁移 broker SID、引用数或任务。当前没有动态订阅能力，不能将该目标描述为现有交接保证。

## 容量与错误

默认值由 [player::Config](../crates/tok-gateway/src/player/config.rs) 定义。常用开发值：连接 128、session 1024、执行/下行队列各 64、帧 1 MiB、完整帧 I/O 15 秒、认证和 RPC 各 5 秒、所有权租期 30 秒/续租间隔 10 秒、主题 64、timer 128、下行缓存 256 条/4 MiB/30 秒。交接默认 15 秒、最多 16 条记录及 8 MiB 快照；各值均需配置校验，不构成生产容量承诺。

登录失败返回 LoginResponse；已绑定业务失败返回关联 request_id 的 BusinessResponse；未绑定或非法控制流程使用 ControlError。业务错误码由游戏维护，系统错误映射有限 ErrorCode，不把内部 Status 文本、凭证和协议正文写入客户端错误或默认日志。

## 迁移验收不变量

- 请求、timer、转发事件的 FIFO 与所有权边界不变，普通服务不因此要求 session。
- 新下行校验/编号/缓存一致，ACK 不越界，补发不重执业务或 Layer。
- 顶号、旧绑定、恢复 token 刷新、同网关恢复及交接取消/超时的身份检查不回退。
- 连接、任务、主题、timer、缓存和准备记录有界；失败和 Drop 的清理不影响新代次。
- 客户端不能以消息 ID、topic、正文或可配置中间件伪造服务器事件/timer。
- 真实 TCP/RPC、NATS 与受影响 Redis 专项按当前计划验证，归档阶段编号不再决定实施顺序。
