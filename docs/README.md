# 文档导航与维护约定

框架围绕“服务 + 处理链”组织。tok-gateway 是基于共同构建、执行和生命周期设施的内置扩展；tok crate 是统一导出与应用组装入口。此为已确认的目标方向；P1 已完成执行原型，P2 已复用公共工厂及生命周期；P3 已接通 RPC/事件/timer 共同处理链和统一事件表，P4 已完成 gateway/session 能力、状态扩展及业务处理链迁移；P5 已完成 topic 传输路由，P6 已完成动态兴趣聚合与主题策略，P7 将汇总迁移与验收。

## 文档边界

架构描述只声明目标与约束，不因为存在接口或目录就标记功能完成。实现状态以源码、可运行示例与已执行验证为依据。P4 网关扩展已进入用户指南和文档测试；P6 动态兴趣已进入指南示例；尚未实现的后续能力仍不放进可运行示例。

服务与事件的目标契约集中在 service-runtime.md；批次顺序和验收集中在 implementation-plan.md；能力状态集中在 status.md。其他文档引用这些来源，避免多份路线互相覆盖。客户端协议的当前规则集中在 client-session.md，历史版本只存入归档。

文档调整不代表代码已迁移。每批实现后同时更新实现状态、实施计划、用户示例及受影响协议；历史记录追加已发生的结果，不回写成新的架构规范。目标与已实现能力冲突时先明确差异，不让用户按未实现接口使用。

代码、配置、协议和文档都是 LF 文本。中文用于解释，Rust 标识符、命令和固定协议名保持原文。提交与协作规则见 [AGENTS.md](../AGENTS.md)。
